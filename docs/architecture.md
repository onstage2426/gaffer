# Gaffer architecture

Where each part lives and how it works, for working on Gaffer itself (`AGENTS.md` points here). Keep it current when a part changes: one row per area.

| Area | Files |
|---|---|
| Boot | `Gaffer::configure()` (theme root + config, no WordPress), `Gaffer::boot()` (Twig, `inc/`, ACF JSON path, blocks, `wp_print_font_faces` off without a `theme.json`, admin bar), `Gaffer::twig()` (SHORTINIT), `Gaffer::version()` |
| Blocks as content | `Blocks::markup()` (public): an ACF block's comment from values by field name, via `BlockFields::group()` (the derived keys), repeaters as count + `name_{i}_sub`, true/false `"1"`/`"0"`, images/files int IDs, links `{title,url,target}`, lists of IDs as strings (as ACF stores them); refuses unknown fields (did-you-mean), layout fields and groups (not written yet: unverified storage); escapes exactly like `serialize_block_attributes()` (round-trips through `parse_blocks()`/`serialize_block()`). Writers must `wp_slash()` it for `wp_insert_post()`/`wp_update_post()` |

Tested through PHP's built-in server (`php -S` with a router that preloads the clone: real uploads need a web SAPI) phpstan knows Gravity Forms through `phpstan/gravityforms.stub` (`scanFiles`) |
| Vite plugin | `resources/vite.js` (`gaffer()`, the theme's `vite.config.js`): `base: "./"`, no `publicDir`, `build.outDir` `public` with the manifest, alias `@gaffer` → `resources/js` (no dev server: removed 2026-11-21), and `public/.vite/gaffer.json` `{js: sha1, files}` on build; `emptyOutDir` off: after a build `prune()` deletes only what neither this build nor the previous one wrote (`files`; before there was a list, nothing), so cached pages keep their assets (`gafferJsHash()`, same algorithm as `AssetsCheck::gaffer_js_hash()`, tested against each other) |
